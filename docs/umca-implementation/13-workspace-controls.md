## Common service and policy

Use same authorized operations from AppWorkspace and ClientWorkspace, corresponding versioned server/proto/client calls and CLI/TUI. Design typed request/response, capability checks and opaque statuses. Native/connected/headless clients use same service semantics: inspect/compact/search/expand/delete, memory review/edit/forget, revoke/retention, etc. No mutating context_search/expand tool; only explicit host-authorized admin. Bounded results and revision-bound cursors; authenticate principal at host, derive resource scope, reject cross-scope and stale/altered cursors. Destructive operations require specific selection/confirmation where applicable; no automatic erasure or remote side effects by model. Handle denied vs unavailable without leaking other scopes. Existing auth/access controls stay intact. Version endpoints compatibly; older clients see explicit unsupported capability. Never use untrusted client-supplied owner/workspace as authority. CLI examples are proposed until names confirmed; choose coherent `crush` subcommands/options following actual Cobra patterns. Document exact implemented commands, help and examples after tests, not invented existing commands.

Config round-trip JSON schema and shellconfig options including inversion, defaults, merging, validation, old configs, effective per-project policy. Use existing experimental patterns; propose independently controlled flags/bounds for UMCA projection, expanded capture/index/retention, deterministic recall, auto-summary spend, learning extraction/reflection/manual, cross-session/personal, remote embedding/reranking/helper, remote store/deployment, MCP exposure, cache/diagnostics/raw export, rewind managed capture/shell scope. Default native operation and local-only; paid/cross-scope/external egress separately disabled. Separate permission from capability detection, runtime per-caller status `implemented/version`, `enabled`, `unavailable_reason`, last successful validation, cost/retention. Disabling jobs cancels/fences late publication, preserves authorized inspection/deletion, fallback tested. No capture deletion implied by toggle. Policy tightening invalidates index, vectors, receipts/excerpts, pending model inputs and shared copies through underlying services. Raw debug/export separate explicit consent, scope and retention. Default logs metadata only; no source handle after revocation. Implement user-facing cost/usage labels unknown vs estimated vs observed; summary does not certify tool effects. Retention docs: logical delete not forensic erasure of SQLite pages/WAL/backups/third-party/user exports, quarantine pre-delete backup, preserve manual edits to exports, older binary downgrade only proven safe otherwise filtered export.
