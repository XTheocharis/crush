## U05 — checkpoint and invalidation

1. Finalization: call message flush barrier **before** DB transaction; snapshot final native version/digest; race deletion while flush pending; conditional finalize prevents resurrection. Native tool synthetic results preserve outcome-unknown. Keep stable ordered identity and separate creation/display order. Legacy ambiguous grouping remains ineligible, expose reason.
2. Publish checkpoint: host prepares summary from frozen contiguous finalized range; outside tx verify completion and structure; begin short tx with expected current lineage rev, predecessor, policy, scope, versions/coverage (half-open byte ranges of named representation), source and lease/admission fence; insert checkpoint and ordered edges; conditional pointer update, require one row affected; rollback all candidate writes on failure. Unrelated tail append only: reread and validate *all* covered versions, eligible prefix, unchanged predecessor, policy and order before rebasing CAS. A zero-row update cannot retry stale prose by just bumping revision. No DB connection held over summarization. Candidate invisibility until commit; recover committed complete pointer or safe reconstructed view/missing range on reopen; sweep orphans. One active pointer per writable lineage.
3. Deletion is a transaction below both native session service and CLI/workspace callers. Discover transitive dependents while edges exist (checkpoint ancestors, original copies, read-result and downstream generated groups, search/index rows, memory/observations/task notes, fork/handoff, legacy pointers). Conservative whole-unit suppression when attribution ambiguous; do not match text to infer provenance. Revoke payload/visibility, increment generations, invalidate published and pending views, record owned files for idempotent physical cleanup; never delete project file or user export. Explicit subtree delete; default retain independent child content, invalidate inherited traced copies. Repeated deletes idempotent. Distinguish forget learned claim from source deletion; suppression metadata minimal and policy controlled. Clear affected legacy summary pointers. For caches/remote projections and later derivatives register dependency invalidation in same transaction or outbox; never rely on FK cascade severing edges first. Reauthorization at use and storage-backed admission claim: deletion-first → new claim loses; claim-first already in flight → cancel best effort, late writes lose. No claim of atomic HTTP or past disclosure erasure.
4. Legacy read/mode compatibility: inspect `ListFromSummary` SQL timestamp cutoff and fallback. Validate pointer ID AND owner/session, kind, complete state and eligibility; foreign pointer with nonempty suffix must fail, not merely zero-row fallback. Reconstruct authorized retained history, no fabricated lineage; same-second cutoff regression. Missing/foreign/non-summary/revoked pointer tests inspect actual request via HST. UMCA→native idle transition validates retained history or new consented legacy summary, atomic boundary+mode; refuse unfit conversion and preserve readable old mode. Disable capture not erase. Test migrated copy with old binary; if bypasses tombstones, forbid downgrade and offer filtered export, no migration rollback on live data.
5. Restart: reconcile unpublished rows/metadata and pending cleanup; verify scopes and ownership, reject stale worker after shutdown, committed pointer complete. Support one connection and multiple independent processes. CAP handles physical files and quota journal, STO owns transaction ordering. Distinguish process-crash consistency from OS/power-loss durability: the reviewed native SQLite setup uses WAL with synchronous=NORMAL. Do not change native pragmas globally just for UMCA or claim power-loss durability without exact selected-driver/filesystem evidence. If a specific durable intent/before-image/authority transition needs stronger persistence, use a scoped justified design and verify it. Document logical vs forensic deletion (SQLite pages/WAL, backups/export/provider copies), restore quarantine and revocation history.
