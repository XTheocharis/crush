**Units:** QA participates U00, verifies G1–G7 and U14. Source §§6–7 (complete checklist), §11 A–I and boundary tests, §8 regression risks, §10 archived fixture mappings. ## Metrics and evidence ledger

Use identical seeded histories/tasks, provider transport fixture and synthetic source corpus for native disabled vs enabled and each stage; same hardware/runtime, warm/cold conditions recorded. Long-running continuation + task change + restart + recall/delete; varied group size, parallel results, provider shapes. Record input prompt bytes and estimated/reported tokens separately, output reserve/actual cap, tool fidelity (exact marker and complete groups), duplicate dispatch/terminal count, DB reads, disk growth incl temp/index, p50/p95 preparation latency and time to first output, retrieval success/recall@k/ranking quality on labeled held-out exact/paraphrase/multilingual/stale queries, total model calls and usage by purpose incl rejected summaries, retries and background, cache reported metrics only, cost known/estimated/unknown, backlog drain and recovery time/loss window. Report sample count and uncertainty; simpler baseline may win. Set measurable thresholds after baseline with ORCH, record before comparison, not arbitrary promises. Invariants (zero observed duplicate effects/leaks/stale publications in fixtures) are binary safety gates, not broad performance guarantees.

Maintain `docs/umca-implementation/acceptance-ledger.md` plus sanitized external logs: requirement section and fixture ID, enabled/disabled/outage/migration state, target+merge SHA, actual provider/DB/OS/worker, exact command, expected observable, observed result, PASS/FAIL/BLOCKED/NOT_RUN, log path, owner, issue/rework and residual risk. Map every §7 checkbox and §11 acceptance/boundary row to owner IDs; do not omit archived regression negative fixtures (equal timestamp, shared block ID, no FTS rebuild, sole-source reversible delete, missing middle, exhausted disk, expired cursor, each transactional write fault). Capture actual command output, do not treat test existence as pass. Review each PR/merge for storage migration, consent switches, user entry point, metrics, rollback and fixture evidence. Use `git diff --check` and validate generated code reproducibility. Independent re-review after fixes. Stop and report specific blockers with safe fallback; no final release if a required stream/adapter has unverified enabled path or unsafe rollback.
