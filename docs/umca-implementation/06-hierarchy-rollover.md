1. Extend rolling checkpoint format to ordered child references and level, lineage, first/last covered event, digest over canonical ordered coverage, predecessor and policy/format. Keep immutable leaves and source versions. Select adjacent finalized eligible siblings on same lineage, reject overlap/holes/cycles/duplicate primary coverage; validate union of children (not model prose). Candidate condensation separate summary call budget, host-admitted, completion-checked, no DB tx during model work. Publish via STO existing expected frontier CAS; validate source revisions, descendants and current policy. A parent may include multiple children. Expand to ordered originals through scoped edges, bounded depth/nodes/bytes and cycle guard; missing/expired/corrupt reported at actual range. Delete middle leaf → invalidate all covering ancestors before next request/search. Test multiple converging paths dedup stable order.
2. Keep one published frontier per independently writable conversation lineage; session ID if branches separate. Siblings' request views independent immutable snapshots. Fork inherits only authorized prefix via recorded point; Git branch names/parent session not proof of lineage. Maintain separate execution vs display order. HST consumes hierarchy on each actual PrepareStep; preserve signed/opaque provider prefixes and mandatory tail, current/folded instructions, outstanding group; no rewrite of Fantasy history assumed.
3. Add compartments typed current task/earlier task/repo evidence/preferences/archive; explicit task boundaries and provenance, not regex inference of authority. Optional detail levels full/excerpt/summary/handle. Score relevance, age, importance/pin and pressure, expose components in inspector with stable tie-break. Reserve mandatory content first, apply pressure bands with hysteresis (derive thresholds from measured adapter budgets; document proposed configuration). Decay presentation only: no truth/authority change, erase, or override of revocation/pin. If pinned+mandatory too large typed conflict. Idle proactive summary frozen prefix, separately opted-in model spend and budget; cancel/invalidate on task/policy/frontier change, discard late publication, on-demand fallback and deadline. Use durable local job contract; never delay critical path for optional job beyond deadline. Track cost of failed/rejected/idle work.
4. Local rollover explicit user/host authorization: idempotency key bound source frontier+recipient+scope+mode, freeze task note, retained tail and pending operation handles. Validate authorized source lineage, create destination inactive, render/budget new view before atomic activation; source continues independently. No synthetic corrected user message or replay of unknown effects; pending work remains handles/unknown, not executable instructions. Redelivered op returns same recipient, changed fingerprint conflict. Both source/recipient retain dependency edges so revocation/expiry propagates; no implicit workspace or Git branch change.
