## Implementation

1. Create distinct user-owned namespace outside project DBs, host-resolved principal, record type/version/scope/evidence policy, source origin/version/grant generation and ownership. Personal records may have independently user-authored assertion; raw project sources stay private unless explicitly granted. Promotion is deliberate user action with preview: claim, evidence scope, recipient projects/principals and permitted operations (read claim vs read sources vs approved egress), scope/version, model/external service receiving text if applicable. Grant policy includes owner, recipient resource set, operations, generation and revocation. Require caller authorization and expected version; repeated op same fingerprint no duplicate, mismatch conflict. Separate capture, recall, personal sharing, storage, model spending, embedding/reranker/MCP consent. No auto-promotion by memory extraction, user preference in tool result or matching repo path. Host verifies recipient bound; children/helpers inherit at most caller grants.
2. Query session, project and personal namespaces separately using current authorization, bound each and fuse eligible candidate sets deterministically. Grant to claim does not grant raw evidence; inspector returns an opaque source-unavailable marker for unauthorized evidence, no text or handle leakage. Read/current/as-of/expansion/native recall/vector/MCP/helper/caches/import fallback all obey current grants and origin eligibility. Origin-dependent claim/derivative must reauthorize before snippet and every actual external admission; independent locally authored records still work offline. Never use replica watermark or recently successful check as proof current origin is accessible. User's independently authored claim may survive loss of raw source only if provenance supports that authority; no automatic laundering.
3. Cross-store records carry origin handle/version, monotonic origin policy/revocation gen, outbox and idempotency; use DST origin admission claim for model egress and live use, remote provisional until eligible. Revoke atomically at origin, invalidate local and remote dependent copies, excerpts, vectors, caches, claims/receipts and queued inputs; publish durable event. Offline destination suppresses origin-dependent material immediately when it cannot validate; on reconnect detect sequence gaps/fetch authoritative state, ignore old upsert after newer tombstone, separate eventual physical cleanup. On revoke-first no new egress; claim-first in-flight limitation explicit. Historical queries and rollback generations obey present revocations. Test absence of sensitive source excerpts in logs, dead letters, exports.
4. Explicit owner-scoped export/import via same service: preview and choose destination, approved representations, versioned manifest of provenance, source generation/status/grants and source availability; never export hidden raw evidence or opaque provider signatures, secret fields. Default metadata-only inspection; export user-selected content only with consent and reauthorization immediately before release. Preserve manually edited user export files (do not delete as owned store file). Validate version/size/digest/paths and scope on import, map collisions to new scoped IDs, reject conflicting replay, check older generations and missing origins. Quarantine pre-deletion backups and missing revocation history, require explicit resolution and deny recall until validated; no restored grants by default. Explain user-owned external copies and third-party past disclosures cannot be remotely erased. Revocation persists across source migration and origin authority epochs.
