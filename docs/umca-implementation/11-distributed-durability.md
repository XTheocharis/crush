## H1 — conformance store and origin authority

1. Inventory all local transactional records and operations (source/version/ordering/edges, CAS frontier, capture/reservations/revoke, admission, operation and job ledger, memory/graph, later hierarchy/rewind). Design storage-facing interface with consumer-owned small Go interfaces, no Fantasy types, no duplicate authoritative transcript. Keep SQLite default. PostgreSQL second transactional UMCA backend with equivalent scoped queries, unique constraints, ordered coverage, CAS, revision and deletion predicates. Implement conformance fixtures shared by both stores; inspect transaction isolation and row locking under races, evaluate clock semantics using DB time. Coordinate STO additive SQLite migrations and versioned PG migrations, safe populated upgrades, generated code per agreed workflow. External vector index is a derivative via C2; no third authority. Explicitly identify which store owns native source revisions and which owns the writable UMCA frontier/job state, and record the active authority epoch. In separate stores a PostgreSQL transaction cannot atomically read or update SQLite; require origin participation at publish/admission and mark remote results provisional with live eligibility on use. Migration cutover changes UMCA write authority, not native transcript ownership. Never present a remote CAS as a distributed atomic transaction.
2. Separate host DB and UMCA DB when configured: write source mutation + outbox atomically **with host mutation**; event immutable versioned payload with stable ID, monotonic origin seq/gen, scoped references not raw content. Idempotent receiver dedup with domain change in same transaction, detect gaps, fetch current state; newer tombstone wins over older upsert. For single-store ops use that transaction for conditional check. For remote projection, origin admission atomically verifies source and policy and records admitted gen; remote write provisional. Recheck live origin eligibility when selecting/returning and before egress (not eventual event receipt/cache/watermark); origin outage suppress origin-dependent records, independently owned unaffected. Monotonic invalidation and eventual cleanup of provisional/stale copies, no promise atomic cross DB/broker/provider. Revoke-first admission fails, admitted-first may still send, cancel best effort and fence late publication. Never hold DB tx across network/model/filesystem operations.
3. Persist operation ledger accepted/dispatched/observed/outcome-unknown/terminal, scope/purpose/operation key/fingerprint, observed result/receipt, retry policy. Stable keys use host operation IDs, reject same key different payload. Unknown external tool/model effect not automatically repeated; provider idempotency only if supported. Build jobs with queued/running/succeeded/failed/cancelled, immutable input refs, policy/source gen, purpose, attempt count, owner, expiry and fence, error metadata. Transactional claim increment fence, DB time expiry; heartbeat current owner/fence still valid only. Commit result + job status + outbox event together only if running/current owner/fence/unexpired/current source+policy. Evaluate DB **current time at conditional update after lock wait** (in PG do not use transaction-start `now()` for this predicate; test lock delay). Expired worker loses authority even if nobody claimed yet. Reassign with increment; transient retry cannot renew source authority or spend permission. Cancel invalidates old publication; late results discard. Local worker implements same protocol; bounded priority interactive vs maintenance and non-starvation, shutdown drain. Worker doesn't execute tools merely because lease expired.

## H2 — broker, workers, migration and recovery

- Implement separately runnable worker binary/subcommand (OPS decides CLI surface) and reference RabbitMQ transport with durable verified topology, persistent messages, mandatory routing, publisher confirms and correlation to outbox event ID, explicit acknowledgments, bounded prefetch and dead-letter route. Positive confirm alone not enough: correlate mandatory return/unroutable, nack and confirm; mark relayed only routed+confirmed, uncertain/lost confirm retry stable ID, alert broken binding. Consumer dedups in DB tx with effect, ack after commit only; duplicates/out-of-order safe. Track relayed vs applied separately. Bounded retry/backoff, inspect failed/dead-letter entries and replay authorized refs only; no sensitive raw data in queues/errors/DLQ. Version event envelope/mixed-version upgrades, tenant/operation-scoped credentials, explicit remote config and spending policy. Broker outage degrade local authorized function or report unavailable, no false empty result.
- Implement source handoff protocol for HIE/PER: pending origin idempotency record/frontier; inactive unique recipient; origin rechecks scope/size/gen and publishes activation decision; relay/redeliver idempotently, visible only active with live origin eligibility; abandoned pending cleanup. REW cross-store journal publication receipt atomic with frontier decision, retry read authoritative receipt before compensation; unknown commit gates affected runs. Distributed worker proposes, owning workspace applies file I/O.
- Migration/export and cutover: create snapshot from authorized data and revocation high-water, checkpointed backfill/catch-up to durable watermark, validate ordered coverage and counts/digests+eligibility; durable authority epoch. Fence old writer at cutover barrier, catch target through barrier, atomically switch authority (one write authority), old workers on reconnect fail. Resume interrupted migration; rollback reconciles post-cutover updates to prior writer before enabling it or stays new, never two active writers. Index shadow generation switches honor present revocation. Explicit remote egress/storage permission; deploy choice never grants content permission. Provide migration/rollback dry-run and progress/repair status.
- Reconcile startup orphan files/pending metadata, unpublished checkpoint, stale jobs, queue lag, outbox/receipts, deletion and recovery. Bounded repair preview/apply, content-free reports, operation IDs, idempotent retries and authorized index rebuild. Backup isolated restore exercise: reapply revocation high-water, quarantine missing deletion history (deny recall until resolved), restore procedure, measured recovery time/loss window. Document limitations for past external copies, filesystem/process crashes and partitions. Stop new admissions, cancel workers, await termination before stores close. Capture quota/recovery retention and pending revocation honored.
