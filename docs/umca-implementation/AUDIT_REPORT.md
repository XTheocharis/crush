## 4. Coverage across artifacts and architecture

All 37 original main nodes retained; U02 dependency changed from U00 to U01; U05 merge-after-G2 recorded in graph, plus per-unit candidate and integrated audit dependencies. New [GATE_CONTRACTS.md](GATE_CONTRACTS.md) splits premature assertions; [ACCEPTANCE_TRACEABILITY.md](ACCEPTANCE_TRACEABILITY.md) covers all 31 core checklist entries plus negative/core/advanced/shared tests. Marker policy preserved and helper strengthened. No reduction to local-only final scope; local is the default safe mode and first milestone, not a substitute for A–I.

The central architecture remains consistent with spec and Go context: native host owns execution/transcript; derived context is projection, not authority; durable stable source identities and ordered coverage; one transactional publisher; host authorization at real boundaries; conservative unknown outcomes; explicit lifetime and bounded work; no automatic new external spend; no extra Go module by default; thin marked hooks and new cohesive files. A/B need checkpoint/memory, C/F recall/invalidation, D bounded read API, E/G adapter fixtures, H cross-store durability, I local capture/frontier/mutation plus H for connected recovery. The reviewed plan makes these dependencies explicit and does not resolve untested engineering choices by inventing APIs or values.

## 5. Remaining verification, limitations and decisions

- No actual Crush code, migration, GitHub file or runtime was changed. No Go build/test, reference project's full test suite, live provider, supported-platform run, PostgreSQL/pgvector/RabbitMQ experiment or independent future agent audit has been executed here. The static inspection does not prove all possible details or future implementation correctness. Current local Go toolchain is 1.23.2, below repo's 1.27.4 directive; live Git clone was blocked by DNS. GitHub connector commit/tree/source verification succeeded. The new helper tests use disposable local bare Git fixture repositories; real fetches remain U00/per-unit checks.
- Exact selected dependency APIs, transitive SDK retries, server trust boundary, platform root/durability behavior, license of any actual reused code, current security patch/advisory and final deployment configuration must be resolved in the implementation environment. Do not claim source examples prove those behaviors. Current refs are a timestamped observation and can move. No need to update reference pins just because branch tips advance.

Any true product/spec/API conflict is recorded and affected decision blocked, not silently ignored.
- The review is a source-grounded planning audit, not exhaustive formal verification. New actual implementation may reveal further conflicts.
