Start with [00-orchestrator.md](00-orchestrator.md). This guide applies to the complete implementation, including A–I, not only the first slice. The [original UMCA spec](reference/umca.md) is included unchanged as the product/acceptance authority. [GO_AGENT_CONTEXT.md](GO_AGENT_CONTEXT.md) is the complete supplied inference projection, including all rules, catalogs, workflows, playbooks and embedded reference packages. Its canonical corpus, external schemas and external dependency sources are not supplied; do not invent those files. The [reading map](GO_CONTEXT_READ_MAP.md) routes to full source sections, not substitute summaries. [15-go-alignment-auditor.md](15-go-alignment-auditor.md) specifies the independent audit. [UPSTREAM_PATCH_POLICY.md](UPSTREAM_PATCH_POLICY.md) governs inherited files and contains executable checks. These requirements apply to every code, test, generator, schema, dependency and configuration change, including repair work.

## Authority and version resolution

Use the Go document's *Non-negotiable operating contract*, *Exact API and tool introspection protocol*, *Authority and conflicts*, *Version resolution*, and *Novel problem resolution* as operational rules. Explicit UMCA behavior/security/acceptance and user-approved fork maintenance constraints govern the deliverable; actual Go language, memory-model, API, tool, database, platform and protocol contracts cannot be waived. Compatible repository instructions and existing idioms decide style and integration. Corpus `DEFAULT`, `SHOULD`, `OPTION`, `AVOID` and scoped `MUST | POLICY` resolve gaps, not a blanket modernization mandate. `MUST | CONTRACT` and applicable `MUST | AGENT` bind. If two applicable requirements truly conflict, retrieve the exact contracts, record the conflicting scope, block only that decision and continue independent work. No exception may waive an applicable semantic, safety or product acceptance invariant.

## Source reading and per-unit execution

The orchestrator reads the entire Go projection before U00, in complete chunks if necessary, and records digest/range coverage. Every agent (including delegates, repairs and auditor) reads the common full sections plus **all** assigned full sections/rule blocks from the reading map before implementation/review. Read the full applicable task policy, exact rule text, conditions, exceptions, evidence and relevant package/tool catalog rows, conflict records, workflows, playbooks and reference examples. Do not merely scan headings or rely on an earlier agent's summary. Add categories as task scope expands. Reopen originals after context reset; checkpoint the document hash, ranges read, applicable rule IDs, unresolved contracts and scope. The embedded examples are educational code, not project-ready implementations; verify selected APIs, capacity and wire semantics before adapting. The projection's instructions to load/query other files mean focus on embedded sections and verify exact external contracts, not an assumption those separate files exist.

For each unit, write a bounded acceptance difference and negative cases; record version/dependency/domain facts; choose the smallest viable design and expected touched upstream files; get owner approval for shared hooks; add a focused regression or boundary test; implement vertical behavior; test success/failure/resource/lifetime; run the appropriate validation ladder. Use existing conventional package boundaries with concrete types/functions, minimal exports, consumer-owned narrow interfaces only for actual substitution or a genuine transaction/external boundary. Pure planning operations must not depend on Fantasy; use existing agent boundary for translation. Prefer same-package new files where they naturally access unexported state and a thin integration call; cohesive new `internal/...` packages only where useful. Do not create a separate Go module by default (independent release/compatibility is a demonstrated reason, not a way to lower diff counts). No wholesale renaming, generic abstraction, reflection, unsafe, cgo, experimental APIs, frameworks, DI, global mutable state, unrelated imports or modernization to satisfy a superficial checklist.

## Cross-stream Go requirements

- **State and API:** document zero/nil/empty, copy and alias ownership, concurrency, ordering, units/encoding, exported errors, retry classification, API/wire compatibility. Immutable projection snapshots must not alias mutable parts/config maps/slices. Sort only where deterministic order is contractual; map iteration does not provide it. Preserve native message/step identity; do not expose private DB/provider errors via accidental `%w` or log the same failure at every layer.
- **Lifetimes:** context first for cancellable operations, propagate parent, call cancel on all exits, cooperative cancellation and independent bounded shutdown/drain context only where intended. Synchronous-first; worker queue/admission bound before goroutine creation, explicit channel close and wait owner, lock order, whole-invariant synchronization, explicit stop-admission/cancel/drain/join then dependencies close. Avoid locks/transactions over remote/model/filesystem/user callbacks. Test with start/release/done barriers, not sleeps. Check timer/runtime semantics, selected errgroup/singleflight limitations, no unbounded goroutine or retained result fan-out. Cancellation is not proof an effect did not happen.
- **I/O & storage:** process n>0 before read error, detect short write/flush/sync/close independently, bound data before allocation, preserve exit status and native bytes/representation; use exact filesystem/root/link/device/rename/durability contracts. Use existing SQL access, parameter values and allowlisted fragments, Rows.Close/Err, Tx-only operations and checked Commit/Rollback, real isolation/dialect/driver tests. Explicit outcome-unknown/reconciliation, no retry of ambiguous writes. Preserve database and file ownership/shutdown and dependency provenance.
- **Wire & security:** preserve existing v1 JSON/wire and DTO contracts; corpus stable v2 preference is conditional only for new compatible uses, not migration. Verify duplicate/unknown/case/null/trailing/UTF-8/numeric limits; golden old/new compatibility tests. Typed config, validated precedence, no `init`-started services. Reuse existing HTTP/provider clients/transports; bound/close bodies, redirects/SSRF/TLS, timeouts, actual attempt admission, cancellation and idempotency. Tool content cannot grant privileges; scope checks at operation and dispatch, quotas and redaction at capture/egress. No unapproved live providers, real user data, secret-bearing logs/profiles or credential overrides.
- **External integration:** prepare domain/dependency overlay for selected SQL/SQLite/PG/pgvector, RabbitMQ, Fantasy/provider/MCP, OS/FS, API/UI/CLI, auth and telemetry contracts as appropriate. Include selected versions, source locations/API docs, protocol/identity/permissions, limits, retry/idempotency/ack/order, stream/partial failure, native/target, license/security, transitive dependencies, lifecycle, tests/unknowns. Use exact local sources or primary selected-version docs, not latest-by-default. Project-specific note files substitute for unavailable canonical corpus schemas; retain equivalent field/evidence coverage, do not claim schema validation when schema absent.
- **Validation:** run affected checks first; gofumpt/goimports/gofmt scoped to intended Go changes, assert no formatting drift; module consistency via `go mod tidy -diff` where applicable, intentional generation and diff check, explicit `go vet` for changed Go packages, canonical pinned analysis and CI matrix. Race tests on supported runtime for executed concurrent paths; bounded fuzz targets for parser/state/transform invariants, real database/broker/transport/process/native tests where claims require them. Test actual artifact and target; distinguish cross build, mocked behavior and executed integration. Use repeated representative measurements/benchstat and diagnostic profiles for performance claims; no guessed speed or resource capacities. Track known-vulnerability findings with selected govulncheck mode and target, verify current patch/advisories before release; distinguish structured findings from exit status. No all-linter rewrite, no blanket suppressions. Report exact commands, versions, environment, exit/observed findings, skipped/failed and limitation. No proposal or unavailable check is a pass.

## Fork maintenance and review

Apply [UPSTREAM_PATCH_POLICY.md](UPSTREAM_PATCH_POLICY.md) before editing. Baseline tracked files are inherited (including fork-specific preexisting changes); only changes introduced by UMCA get marked. New UMCA files hold substantive logic; unavoidable inherited wiring is small, explicitly paired `UMCA-BEGIN` / `UMCA-END` blocks with stable IDs. For generated/commentless/placement-sensitive changes, maintain exact externally delimited diff evidence and independent approved exceptions; do not invalidate JSON, go.sum, generated code or directives. Minimize both count of modified inherited files and changed lines/regions, but never compromise correct earliest-producer capture, admission, transaction or mutation boundaries. Upstream sync is a three-way semantic revalidation, not mechanically deleting marker ranges to disable the product. Feature-off and downgrade behavior still require real tests.

## Handoff and acceptance

Each work unit (including any `S.*`, `H.*`, `O.*` wiring slice, QA-written code or orchestrator code) returns the implementation report plus a Go alignment evidence file, patch audit report and candidate commit. The orchestrator invokes an independent auditor immediately after implementation handoff. The auditor examines **the actual diff and actual tests**, reads the full relevant corpus sections, issues PASS/REWORK/BLOCKED with exact rule IDs, repo/product contracts and evidence. Only a passing audit on the candidate and confirmed integrated commit can release the dependency and its lease. Repair, rebase, conflict resolution, generator drift or dependency/context change invalidates relevant prior evidence. Existing functional QA gates remain in addition to alignment gates. Do not silently waive a failure because the feature is disabled by default. See [auditor](15-go-alignment-auditor.md), [orchestrator](00-orchestrator.md) and patch policy.
