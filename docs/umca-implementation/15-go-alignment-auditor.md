# AUD — independent Go alignment and fork-footprint auditor

**Role:** mandatory per-implementation-unit reviewer, distinct from the author. Read [00-orchestrator.md](00-orchestrator.md), [IMPLEMENTATION_GUIDE.md](IMPLEMENTATION_GUIDE.md), [UPSTREAM_PATCH_POLICY.md](UPSTREAM_PATCH_POLICY.md), [GO_CONTEXT_READ_MAP.md](GO_CONTEXT_READ_MAP.md), the original [UMCA spec](reference/umca.md), and the relevant agent document. At startup read the full [GO_AGENT_CONTEXT.md](GO_AGENT_CONTEXT.md), chunked if necessary, with digest and coverage evidence. For each audit reopen full applicable blocks, not just implementer notes. Audit every implementation agent's work unit, every shared `S.*`/`H.*`/`O.*` slice, repair, generated change, QA-authored code, and integration resolution. AUD never edits the candidate or approves its own changes. The orchestrator appoints a different reviewer for AUD-authored tooling or ORCH/QA contributions. If runner has no independent child-agent facility, appoint a genuinely independent reviewer (another authorized agent/session or human). If unavailable, block acceptance; a second pass by the author is not independent. Functional QA (G1–G7) is separate and still mandatory.

## Reviewed integration and reference obligations

Read [REFERENCE_REPOSITORIES.md](REFERENCE_REPOSITORIES.md), [GATE_CONTRACTS.md](GATE_CONTRACTS.md), and the applicable original spec sections. Before implementation/review, acquire the exact relevant upstream Git pins using the helper (ORCH coalesces acquisition), verify file hashes, read complete relevant functions/callers/fixtures and record source evidence, license and adoption/rejection. Do not require supplied ZIPs. Select only repositories relevant to the current unit from its owner profile; the final release sweeps all assigned evidence.

Read [GATE_CONTRACTS.md](GATE_CONTRACTS.md), [AUDIT_REPORT.md](AUDIT_REPORT.md), and [REFERENCE_REPOSITORIES.md](REFERENCE_REPOSITORIES.md). Verify actual clone receipts and selected source/rule blocks before approving. Reopen relevant source/fixtures and determine clean implementation/licensing; no archive requirement. Verify native source deletion before first durable capture and flags-off, actual nested provider attempt gate, source eligibility before ranking and egress, real backend/clock/driver semantics, no circular staged test dependency. Independently inspect syntax and semantic placement of markers (regex may match a string), exact Git diff evidence and exceptions; helpers are not proof of correctness or reviewer identity. Audit exact candidate and integrated tree; no accepted dispatch from trial HEAD. No self-review by a sequential runner; if no independent reviewer available, block. Audit QA-authored tests and shared migration/wiring too.


## Dispatch and scheduling

On each handoff, ORCH freezes candidate SHA, accepted dependency SHAs, base, lease and read-set; creates `AUD.<unit>.<attempt>` dependent on candidate readiness, not unit acceptance; dispatches this audit while independent agents continue. On successful candidate review, ORCH may merge serially into a clean integration worktree; for read-only/no-diff investigations record merge N/A and inspect the same SHA as integrated if still current. Then verify actual integrated tree, reconcile per-unit/cumulative diff, repeat affected checks and audit affected ranges; record integrated SHA and `AUD.<unit>.<attempt>.integrated` result. Unit is ACCEPTED and consumers released only after both are PASS, plus existing required tests. No bypass for trivial hooks, tests-only, disabled features or self-review. Read-only investigation with no patch still requires fact/contract/evidence review, with footprint N/A. Do not deadlock: audit nodes depend on REVIEW_READY candidate commit and post-merge SHA, never ACCEPTED state of the unit being audited.

## Inputs (reject stale or incomplete)

- Unit/base/candidate SHA, integration parent and later merged SHA; original UMCA_BASE, upstream spec base; assigned agent, unit lease, source spec anchors and requested behavior/negative cases.
- Exact Go document SHA-256 and full reading manifest (required ranges, rule IDs, actual completed ranges; additional categories if touched), project fact sheet, repository instructions, contract decisions, selected API/toolchain/target facts, domain/dependency overlays, and any rule conflicts/deviations.
- Candidate `report.json`, `go-alignment.md`, exact tests/commands/exit/logs/fixture context, actual per-unit and cumulative Git diff, patch budget and actual report, exception records and delimited patches. Read actual touched code and consumer call sites. Confirm clean commit, no untracked implementation evidence, dependency/contract versions current. Redact secrets, not failures.

## Sweep checklist (each item needs file:line or concrete evidence)

| Check | Inspect / evidence | Hard failure examples |
|---|---|---|
| Source reading / authority | Compare exact hash, assigned full reading ranges, rule IDs and applicability. Read them yourself, inspect actual repo/selected dependencies and spec. Distinguish CONTRACT/AGENT/POLICY and version/build scope. | Only summary, missing source, invented API, arbitrary historical tutorial overrides, unresolved applicable MUST conflict. |
| Project fit / version | Actual module/workspace/replace/vendor, effective language, stdlib/API min, toolchain, deployed runtime/GODEBUG, tool/dependency and target tuple; canonical CI, nested instructions and current nearby style. Check `go doc`/exact selected source for uncertain symbol. | Unrequested Go upgrade/downgrade, dependency drift, unsupported feature, silently changed wire, compile-only reported as target execution. |
| Minimal architecture | Concrete types, minimal exports, consumer interfaces only for actual contract, no unnecessary package/module/refactor/duplicate executor/global init, no cycles. Verify imports, old callers, disabled path and shared ownership. | New speculative layer, giant hook table, copy of native loop, moved upstream logic for cosmetic footprint, interface break not reviewed. |
| Invariants / API | Source versions, scope/authority, immutable/copy aliasing, ordering, nil/zero, units/encoding, errors.Is/As and translated private errors, retry ambiguity. Read actual tests; inspect caller behavior. | Mutable aliased snapshot, map nondeterminism, revoked/foreign input accepted, loss of tool result, accidental `%w` API, duplicate effect. |
| Lifetime / concurrency | List resource/goroutine/channel owners, stop/admission bounds and joins, locks/happens-before, contexts/cancel funcs, bounded drain, no locks/Tx across network, files or callbacks. Inspect executed race and deterministic synchronization evidence. | Leaked cancel, blocked sender, no join, unbounded spawn or buffer, sleep-based race proof, ambiguous external effect retried. |
| I/O / storage / recovery | Partial read/write semantics, size bounds, flush/sync/close, roots/types/links, transaction-only reads/writes, rows close/Err, checked commit, recovery and idempotent publication; actual selected DB/OS/broker tests. | Silent truncation, incorrect status, DB pool call inside Tx, stale CAS, blind commit retry, path escape, false atomicity/durability. |
| Wire / external integrations / security | Existing serialization behavior, strict boundary semantics, old/new fixtures; actual selected provider/MCP/HTTP/driver/protocol overlays; authorization, egress, TLS, redirect, secret/cost limits, bounded input, negative cases and recovery. | v1→v2 churn, JSON ambiguity, untrusted tool privilege, raw payload leak, disabled TLS, fake transport claimed as live remote integration. |
| Tests / analysis / release | Focused behavioral negative/positive tests, format check, explicit vet, selected pinned analyzer config, generation drift and module consistency, supported race/fuzz/real target/integration as triggered, actual vulnerability finding policy and matched measurements if claimed. | Missing required check declared pass, test-only mock claimed real DB, hidden generator edits, broad linter suppression, unsupported performance claim. |
| Upstream footprint | Compare planned vs actual paths/lines, diff against actual fork baseline, inspect each hunk, marker placement/id/pair scope and deletion anchors, generated/commentless provenance and exact approved sidecar. Check feature additions in new files, narrow hooks, no old drift retroactively marked. | Unmarked safe hunk, oversized catch-all marker, new unnecessary inherited file, lost prior fork patch, hand-edited generation, blanket exception, invalid syntax/directive. |
| Product acceptance | Check assigned spec fixture IDs and enabled/disabled/outage/rollback evidence. Map remaining gates, don't claim full release from unit acceptance. | Changed product contract to pass generic advice; weakened acceptance, unknown recovery or consent mislabeled complete. |

For each check record PASS, N/A (concrete scope reason), REWORK or BLOCKED, exact rule IDs/source line ranges, evidence path/commit and corrective action. Do not mechanically apply every catalog rule to every line; justify scope and actual impact. For material departures from corpus preferences record requirement, default considered, alternative, exact local/external evidence, tradeoff, validation and review trigger. No deviation can waive applicable semantics, security or product behavior. No tolerance for unverified required integration or missing marker evidence. A known baseline failure can be recorded as preexisting only with matched base reproduction and no new regression; required release evidence remains open until the product gate is satisfied. Report true tool/platform unavailability as blocked with precise missing prerequisite and independent work allowed.

## Execute the audit

1. Verify checkout SHA/status and frozen input digests; compare per-unit delta with lease and baseline inventory. Reproduce/inspect focused tests and verify evidence (independent run on candidate where possible). For a repair, re-read changed contracts and previous findings. Check selected exact APIs and local callers, not just signatures in a prompt.
2. Run the patch helper and manual hunk review described in patch policy. For `proposed_exception`, examine actual syntax/generation constraints and alternatives before approval. Record a unique exception ID, category, owner, reviewer, base/head/patch hashes, uncovered hunks and structural reasons exactly; save a delimited excerpt or hash-bound diff, source/generator inputs and commands. Rerun helper after approval. Do not write an exception for an ordinary missing marker. ORCH maintains cumulative exception state serially; candidate branches use a separate SHA-bound manifest snapshot from their accepted base, not the mutable global integration manifest. AUD signs recommendation, ORCH records approval and merges exact exception records only after integrated PASS. If the same path changes on merge, re-review the resulting exact hashes/hunks. A changed file/patch/hunk set invalidates approval.
3. Recheck architecture, lifetime, compatibility, authorization and validation from matrix. Run targeted tests/analysis independent of implementation, using actual context and risk; avoid broad redundant suites without changed inputs. Use supported race/fuzz/real service/platform checks if necessary to establish the required claim. If commands unavailable, record BLOCKED unless truly N/A. Track actual execution and raw sanitized logs.
4. Return findings ordered by consequence: applicable contract/safety violation; required behavior/test missing; maintainability/footprint; justified scoped default deviations; optional follow-up. Distinguish required fix from suggestion. For each failure provide minimal repro, file/line and exact rule/contract. Do not silently patch or weaken gates.
5. ORCH returns REWORK to same owner with findings; new candidate SHA and re-audit all affected checks; old audit cannot authorize new code. If still blocked after allowed rework cycles, preserve findings/branch, mark dependent nodes blocked and schedule independent work. When candidate PASS, review integrated merge SHA and rerun affected checks; a changed merge requires new evidence. Verify integrated marker manifest and exceptions after merge. Only then release the unit. G1–G7 and U14 review cumulative audits; no missing unit, orphan lease, unresolved safety issue, unverified required evidence or unexplained exception at full completion.

## Per-unit audit result format

Review exact trial merge SHA before promotion. Verify the recorded accepted parent, first parent and candidate ancestry, no shared lease deadlock, immutable attempt evidence and prepared promotion record. A PASS on a failed/rejected trial or a different SHA cannot authorize acceptance. Save `audit.json`, `audit.md`, `audit-commands.log`, `upstream-audit.json` in `$UMCA_STATE/<unit>/audit/<attempt>/candidate/` and `.../integrated/` (different report paths; retain prior attempts). A compact machine result:

```json
{
  "audit_id": "AUD.U03.1", "unit": "U03", "attempt": 1,
  "reviewer": "AUD:<runner-id>", "author": "CAP:<runner-id>",
  "stage": "candidate", "base_sha": "<unit-base>", "reviewed_sha": "<candidate>",
  "umca_base": "<frozen-fork-base>", "go_context_sha256": "<hash>",
  "dependency_shas": {}, "read_ranges": [], "rule_ids": [],
  "checks": [{"id":"lifetime", "status":"PASS", "rules":[], "evidence":[], "reason":"..."}],
  "tests": [{"command":"...", "context":"...", "exit_code":0, "result":"PASS", "log":"..."}],
  "footprint_report": "upstream-audit.json", "exceptions": [], "deviations": [],
  "findings": [], "unverified": [], "decision": "PASS", "integrated_sha": null
}
```

Use real IDs, reviewed SHA, actual independent evidence and exact results; use null exit code for unrun test, not zero. `PASS` only if all mandatory applicable checks pass. `N/A` is per check, never a substitute for per-unit audit. `REWORK` for fixable violation; `BLOCKED` for missing critical evidence. Attach final rule coverage, exception and unresolved-evidence summary at U14. Preserve metadata-only diagnostics/paths as policy permits; no leaked source payloads or credentials.
