## Acquire lazily, by task

ORCH owns a separate `UMCA_REFS` directory outside all implementation worktrees, with no reference code vendored into Crush. At U00 verify availability of the target, historical XRush and selected Fantasy source for HST/STO. Acquire the relevant reference repository(s) before each unit's design and implementation, then reuse the verified bare repository by other units. QA and AUD reopen the same relevant source for each unit; `--role QA` or `--role AUD` lists all 20, not an instruction to clone all before each review. Use `--id` for the active unit's actual subset. The helper does not execute reference code, dependencies, hooks, builds, generators or submodules, and never checks out files. ORCH serializes acquisition for each ID in a private owner-controlled root; paths within any Git worktree or repository directory are rejected; private mirrors require explicit approval and identical Git object identity. No clone into the working tree, no arbitrary scripts, no secrets in URLs. Network failure is an evidence blocker for the affected decision, not permission to invent or silently use HEAD. An approved exact Git object mirror is equivalent only after verification; optional historical archives may corroborate blobs but are not the acquisition path. Do not require all 20 online to start unrelated units.

```sh
# Set these absolute directories once; keep outside all worktrees.
export UMCA_REFS="$UMCA_STATE/references"
python3 "$PLAN_DIR/tools/acquire_references.py" --manifest "$PLAN_DIR/reference/repos.json" --root "$UMCA_REFS" --role HST --list
# After selecting required repository(s), acquire exact pins:
python3 "$PLAN_DIR/tools/acquire_references.py" --manifest "$PLAN_DIR/reference/repos.json" --root "$UMCA_REFS" --id pi-tuck-main
# Inspect actual source and surrounding tests; the manifest gives paths/ranges.
git --git-dir "$UMCA_REFS/pi-tuck-main.git" show 499248a0cab903dbc31fc7f01e82d92396283a63:src/request-capacity.ts
```

The helper uses `git init --bare` followed by a bounded fetch of the exact commit (a narrow clone of pinned objects). If the server refuses a direct SHA fetch, ORCH may perform a normal bare Git clone of the verified URL into a temporary separate cache and fetch any necessary reachable ref; verify the exact manifest commit/tree/blobs before publishing it. Never substitute a new commit just to make acquisition succeed. The helper may be rerun against that verified bare cache.

Helper validates SHA-1 commit/tree object bytes and every listed blob against the exact pinned tree, publishes only a fully verified cache, and emits a receipt. Record actual clone/verification evidence and the source ranges read in each unit report, design borrowed/rejected, license (including nested files) and clean implementation rationale. For a new dependency/copy require separate permission, license/notice and exact API/Go compatibility review. A pattern in TypeScript/Rust/other code is not a Go API; never copy implementation without verifying license and behavior. Historical test names are inspiration, not a claim of Crush conformance. If newer commits matter (e.g. fixed vulnerability), inspect them separately, log diff and approve changed design/pin; do not silently substitute latest branch. No automatic dependency upgrade.
