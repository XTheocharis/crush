# UMCA for Crush: architecture, implementation contract and acceptance specification

**Target:** charmbracelet/crush at `0b0c79e32ada5c1e5ba26180023be740f0530f7b`. **Historical comparison:** XTheocharis/crush at `dc96baac1c4c25bd3bcd164cea030d90fc3977e9`. **Status:** proposed design and acceptance criteria. This document is the consolidated implementation specification. The code citations distinguish observed behavior from design requirements. Archived references identify the inspected source snapshots, with hashes in §10.

**Full delivery scope:** §§2–7 specify the shared foundation. §11 specifies all advanced functionality, including workspace and conversation rewind in §11I, implementation dependencies, enabled paths, failure behavior and acceptance tests. §§8–10 provide historical evidence.

## 1. Outcome and design authority

A long-running tool-using session must survive a context reduction without executing a completed action twice, losing an outstanding tool result, dropping an active instruction, or exposing another session’s data. Within an authorized scope, a user must be able to inspect what was captured, recover retained material within its retention policy, and delete it along with its attributable derivatives. A summary may lose nuance even when every retained original is recoverable. Offer exact expansion and distinguish observed, inferred, planned and completed work in both the view and inspector. The first milestone proves those guarantees on the native Crush path. Full delivery includes the advanced stages in §11 and their enabled-path tests. Start with one rolling checkpoint, a protected live tail, bounded tool artifacts and lexical recall. Persistent learning is a later, independently enabled capability.

History records what the application actually observed. The context projection orders the material eligible for one request. Memory contains attributed claims that may be stale, contested or revoked. A terminal event is evidence that the host observed a result, not proof that every external effect succeeded. Keep these distinctions visible to users and in the data model.

## 3. Persistence and transaction contracts

Proposed logical records below describe responsibilities; combine tables where existing upstream rows already express them. Generate opaque globally unique IDs. A handle is a locator; authorization is separately derived from the calling workspace/session and explicit sharing policy.

| Record | Minimum fields and rules |
|---|---|
| Session projection | Session ID, relevant content revision, active checkpoint ID, publication generation. Increment on source/projection changes, including deletion. Exclude unrelated title, cost and UI writes. |
| Checkpoint | ID, session, predecessor, captured revision, stable covered frontier, summary text, policy/format version, state. Keep coverage of earlier checkpoints traversable after repeated compaction. |
| Coverage edges | Checkpoint ID and ordered finalized source references. Include message and stable part identity, content digest/version, optional byte range with defined encoding, and dependency on preceding derivations. Specify ranges as half-open byte offsets into the identified representation. Reject mismatches. |
| Artifact | Scoped ID, capture origin, representation, byte counts observed/retained, digest of retained bytes, completeness, retention state, storage locator. Distinguish complete, capped, failed, expired and revoked. Expose which ranges a preview represents and which were omitted, dropped or expired. |
| Later memory | Scope/owner, claim, source edges, source authority, creation/update time, review state, supersession/conflict relation and deletion state. Separate transient task state from accepted cross-session preferences. |

**Publication protocol.** Read a consistent snapshot of finalized groups and their revisions. Release the database connection before summarizing. On completion, begin a short transaction, validate the expected revision, source digests, scope and predecessor, write checkpoint and edges, then publish its pointer using a conditional update. On zero rows affected, roll back the attempted publication. Reuse the candidate only after the append-only validation described under Publish checkpoint in §7; otherwise replan from fresh inputs. Use the transaction handle for every query inside the transaction, including reads and cleanup. Do not retry a stale summary unchanged. Concurrent deletes and writers in separate application processes must obey the same storage predicate.

**Restart and recovery.** Unpublished candidates are invisible and collectible. A committed pointer must refer to complete rows. If validation fails after reopening, rebuild a legal view from retained history or report the missing range. Never regenerate a persistent ID from a process-local counter. Interrupted external tool work remains outcome-unknown unless an authoritative result or idempotency key permits reconciliation. Stale workers must fail publication after cancellation, scope changes or shutdown. Stop admitting jobs, cancel workers, await their termination, then release the DB.

**Legacy sessions.** Recognize an existing summary pointer as a legacy replay boundary with unknown coverage. Resolve a legacy pointer by target ID **and** owning session, summary kind, completion state and current eligibility before accepting it. Missing, foreign, revoked or malformed targets trigger reconstruction from the authorized retained history. At this baseline, ListFromSummary falls back on zero rows. Its SQL obtains a cutoff timestamp by message ID alone: a foreign-session pointer can select a nonempty suffix of the requested session, so the zero-row fallback never runs. Test missing, foreign, non-summary and same-second targets, and assert the actual request contents. [Timestamp cutoff SQL](https://github.com/charmbracelet/crush/blob/0b0c79e32ada5c1e5ba26180023be740f0530f7b/internal/db/sql/messages.sql#L1-L20) · [Empty-result fallback](https://github.com/charmbracelet/crush/blob/0b0c79e32ada5c1e5ba26180023be740f0530f7b/internal/message/message.go#L537-L562) · [ID-based slicing](https://github.com/charmbracelet/crush/blob/0b0c79e32ada5c1e5ba26180023be740f0530f7b/internal/agent/agent.go#L1927-L1946) Do not fabricate causal order from timestamps or infer source lineage from similar text. During rollout, keep a readable legacy history path and test downgrade on a copy of a migrated database. Turning off new capture does not erase existing data; deletion remains available. Change replay mode only at an idle boundary. For UMCA → native, invalidate obsolete legacy pointers and rebuild from the retained, authorized history if it fits. If a new legacy summary is required, obtain permission for the model call under the active policy. Publish a valid compatibility boundary and the transition together. If conversion cannot fit or retained evidence is insufficient, leave the session readable in its prior mode and give the user an explicit recovery choice. Do not dual-write competing active summaries. An older binary bypasses new policy and tombstones; before supporting downgrade, verify on a disposable copy that it cannot replay revoked native transcript or derived rows. Otherwise declare that database version unsupported for downgrade and provide a filtered export.

## 4. Request algorithm and overflow handling

1. Snapshot the effective provider/model, context window, output cap, tool definitions, protected instructions, finalized group frontier and current in-flight state. Treat signed/opaque continuation data and provider-required prefix segments as indivisible. Resolve concurrent tool calls by their owning step and native call IDs. Preserve protocol order within the complete group.
2. Start from protected instructions, required provider state and complete recent groups, including outstanding calls and their results. Fold a published checkpoint into its covered prefix once. Keep an execution-order record where persisted creation order differs from what the model saw. A summary is labeled derived context and cannot promote quoted tool data to instructions.
3. Estimate all serialized components, including schemas, tool descriptions, attachments, framing, reasoning-related fields and the checkpoint. Reserve output and actually apply the negotiated output cap on the outgoing request. For unknown windows expose an unknown capacity and use existing provider behavior or an explicit configured bound. A character count can inform an estimate; it cannot certify provider acceptance.
4. Reduce optional recall, previews and older completed groups first. Where necessary prepare a checkpoint from a contiguous legal prefix. Budget the summarizer as a separate model call with its own prompt, schema and output limit. For one oversized group use bounded representation/segmented input where legally possible, else defer with a reason. Minimum group counts must never override available capacity.
5. Check final adapter-visible structure and size where observable. Where exact tokenization is unavailable record the estimate and its uncertainty. If the provider rejects context size, allow a bounded replan only before new irreversible work or output requires reconciliation. Keep authentication, rate limiting, transport errors and context-size errors distinct. If required groups alone exceed capacity, surface that cause with recovery choices; never silently delete one half of a tool exchange.
6. Record the run/step and checkpoint IDs, revisions, policy version, capture status, estimated components, selected model, available usage and reduction reason in bounded metadata-only diagnostics. Raw payload capture requires separate consent, scope and retention. Stable prefix bytes can be verified in adapter tests; remote cache hits are measured separately.

### Admission and source invalidation

Treat two views separately. The **stored frontier** is the last committed checkpoint and its exact dependencies. The **dispatch view** is a disposable, ordered request snapshot. Record its settings revision, effective wire type, eligible sources and tool catalog generation. A single-step mapping can reference the same immutable source more than once for explicitly labeled recall. It may represent each covered execution group only once in primary history. Use an adapter's actual rendered request for the final structural check when exposed. A byte or token estimate from the planner remains an estimate after passing that check.

Apply final admission **per actual provider attempt**, including built-in retry and credential refresh. A retry of an unchanged, pre-execution request can reuse its projection after reauthorization. A change to a source, tool manifest, authoritative instruction, wire type or effective policy requires a new admission and, when necessary, a new projection. Honor the host's accepted-model pin. Use separate budgets and purpose tags for summary, learning, helper, reranker and rerouted calls. A dependency may expose a streamed event before returning an error. Track output and tool admission as independent facts and prove the retry path cannot repeat an effect after either has escaped the replan boundary. Record the source dependencies even with user-facing request diagnostics disabled. [Fantasy attempt and stream-processing boundary](https://github.com/charmbracelet/fantasy/blob/475f1439cf21dbed6ca44fe41b4be478a82d119b/agent.go#L985-L1027) · [Crush model refresh](https://github.com/charmbracelet/crush/blob/0b0c79e32ada5c1e5ba26180023be740f0530f7b/internal/agent/shared_models.go#L141-L150)

Evaluate context fit from a breakdown of mandatory, removable and reserved components. When usage is available, compare only like-for-like attempt classes keyed by wire type, model and relevant render settings. Keep the sample count, estimator version and provider fields used. Retain a conservative fallback when samples are sparse, incompatible or missing. Prove that a smaller response ceiling reaches the wire and that a calibration change cannot expand a declared hard provider limit. Crush estimates some missing step usage; preserve the reported-versus-estimated distinction when calibrating. [Crush step usage fallback](https://github.com/charmbracelet/crush/blob/0b0c79e32ada5c1e5ba26180023be740f0530f7b/internal/agent/usage_fallback.go#L9-L36) · S09 in §10.

## 5. Artifact lifecycle, recall and deletion

Stream bounded chunks to temporary storage with quota reservation before bytes are discarded. Track stdout/stderr separately where the producer provides that distinction. Preserve binary data or explicitly mark an unsupported representation. On process completion flush, verify byte count/digest, close and publish metadata; reconcile orphan files and dangling metadata after crashes. On ENOSPC, permission failure or quota exhaustion, allow a bounded preview with a truthful partial/failed status. Do not change the tool’s actual exit status. Use restrictive permissions, scoped lookup and opaque store-owned paths. Enforce quotas atomically across concurrent producers. Retention cleanup must handle active readers and repeated deletion.

Recall defaults to the authorized current session. Explicit sharing can widen scope only after host authorization. Apply scope inside SQL before ranking and limiting, for direct ID expansion as well as search. Index finalized changes and invalidate on deletion; make schema capability detection explicit for each SQLite driver/build. A bounded scan of eligible sources can serve installations without FTS. Generate parameterized literal FTS expressions for plain-text search. Validate any separately supported query syntax, bound query size and time, and use a deterministic tie-break for equal scores. When adding triggers to an existing content table, run a scoped backfill or rebuild under the migration protocol. Prove both preexisting-row visibility and subsequent trigger maintenance. [XRush trigger example](https://github.com/XTheocharis/crush/blob/dc96baac1c4c25bd3bcd164cea030d90fc3977e9/internal/db/migrations/20260517000000_lcm_gaps.sql#L29-L54) · [SQLite rebuild implementation](https://github.com/sqlite/sqlite/blob/version-3.51.0/ext/fts5/fts5_storage.c#L837) Bound total returned bytes and estimated tokens as well as row count; page large entries with a revision-bound cursor. Treat snippets and memory text as untrusted data, and verify retained bytes against the stored digest on expansion.

Deletion starts from source IDs while their lineage still exists. In one transaction discover all dependent checkpoints, original-content copies, task state, observations and index records; revoke access, invalidate projections, increment relevant revisions and record pending physical cleanup. Preserve enough non-content bookkeeping to finish cleanup idempotently. Include derivatives copied into later messages where the host tracks that provenance. Document the limits for pasted text, third-party providers, backup media and user-edited exports; never imply retroactive erasure from a request already sent. Test child sessions explicitly with an intentional retain/delete policy. Reauthorize a prepared request immediately before dispatch when deletion can race it. Any worker completing after revocation must discard its result.

## 7. Builder’s contracts

### Delivery boundaries and ownership

Implement the six core increments in §6 and the nine required capability streams in §11 in dependency order. Capture and checkpoint storage can proceed independently once source identity, scope and error contracts are agreed. Live projection depends on both. Memory depends on working deletion and authorized recall. One implementer owns each migration and its generated code. One integration owner owns the agent-loop diff. Run each increment through the ordinary CLI/workspace entry point before declaring it complete. The first vertical slice is a release gate, not the end of UMCA: deliver manual memory, automatic opt-in learning, branch-aware task continuity, bounded retrieval and inspection to complete the functional scope.

Keep existing Crush sessions usable at each increment. Treat one or more implementation PRs per increment as an organizational choice; a single maintainer can implement and verify them sequentially. A proposed type or method below is an implementation contract, not an API that already exists. Use host types directly where they encode the same semantics. Confirm filenames and function signatures again if rebasing.

### Integration spike and ownership of step state

The pinned module uses Go 1.27.4 and Fantasy v0.48.2. In Fantasy’s agent.go, PrepareStepResult exposes Model, Messages, System, ToolChoice, ActiveTools, DisableAllTools and Tools. It has no per-step output-token field. In both generation and streaming, supplied messages become step input. Treat this as a per-call projection; use the next callback’s actual options as the new input. Do not mutate the callback slice in place or assume a one-time truncation rewrote Fantasy’s accumulated history. [PrepareStep types](https://github.com/charmbracelet/fantasy/blob/475f1439cf21dbed6ca44fe41b4be478a82d119b/agent.go#L99-L126) · [Generate reconstruction](https://github.com/charmbracelet/fantasy/blob/475f1439cf21dbed6ca44fe41b4be478a82d119b/agent.go#L449-L507) · [Stream reconstruction](https://github.com/charmbracelet/fantasy/blob/475f1439cf21dbed6ca44fe41b4be478a82d119b/agent.go#L901-L972)

1. Start with `internal/agent/context_replay_test.go`. Extend the recording model to capture the effective Fantasy call for each step. Exercise at least three steps in one accepted run. Force a model refresh, queue a correction between steps, and change the available tools. Establish which settings arrive before and after PrepareStep. Use a fake transport when asserting serialized provider content.
2. In `internal/agent/agent.go`, identify the source of each folded prompt, settled tool exchange and still-live part before representation-changing transformations. Preserve ordered identities in run-local state; a hash of text is only an integrity check. Two identical user messages need distinct IDs. A fully settled earlier assistant step can be summarized within the same user turn. Treat one assistant emission and all its required tool results as a unit. Fantasy buffers dispatch until the stream has ended, dispatches only on a tool-calls finish, waits for parallel calls, then sorts results by call order. A pending group is therefore an eligibility test for compaction and storage, rather than a new mid-group model dispatch event. If any sibling call from that emission is pending, protect the entire group, including already returned siblings.
3. Apply the projection consistently on every subsequent preparation. Reapply native media conversion, prefix and cache-option logic in the order required by the adapter. Recalculate after dynamic tool filtering. Preserve original native parts for replay, including opaque signatures. 4. Bind final admission to the selected language model on every construction path. `internal/agent/coordinator.go` already wraps language models with a request **timeout** guard. 5. Let the existing run own queue draining, permissions, cancellation, tool effects and RunComplete publication. No synthetic user prompt to resume a reduced run. Maintain the mapping from projected step to original source frontier. ### Source identity, projection and budget examples

Treat a scope as a host-resolved principal plus allowed resource set. Session, workspace/repository, branch or revision, subagent and channel may further restrict it. Never derive the owner from an LLM tool argument or a prompt string. Native source identity is the persisted message/part identity or a host-issued event identity. Track stream order and a finalized version separately from message creation time. When a source changes, invalidate the covered version. Persist a host ordering key and an intra-group call ordinal for new events. A tool call key includes its owning run/assistant step and native call ID. A repeated ID in another step cannot settle the original group. Old sessions with insufficient order evidence use a deterministic tie-breaker for display and are labeled legacy. Recover valid grouping from native call links where possible. Mark ambiguous ranges ineligible for automated compaction until their provider sequence can be reconstructed or the user chooses a supported recovery.                        ↓ after G5 is finalized and eligible

G7 may include multiple dispatched calls. Keep the initiating assistant part and all corresponding results required by the provider. Never remove an unresolved group merely because its launch occurs before a chosen position. If a legal contiguous cut cannot advance, retain that segment and report why. Store host-computed coverage, predecessor and protected constraints independently of summary prose. Reject empty, truncated, stale or structurally invalid summaries. A deterministic excerpt may be published only with its actual representation and coverage and only if it satisfies the same structural rules.

For a shared 128,000-token window and an enforced 8,000-token output cap, the gross input allowance is 120,000. A separate 100,000 input limit lowers it to 100,000. Subtract margin and required content from that allowance. For independent input/output windows use the declared input window directly and clamp output separately. Never treat cached tokens as free context capacity. Multimodal and reasoning counts are provider-dependent. If exact counting is inaccessible, expose estimated admission; do not assert a precise final wire count. Stop reduction when the measured candidate stops shrinking or no eligible content remains. For provider overflow, permit at most one smaller replan for the same logical step across all transport/auth attempts. Record the allowance on the run/step. A terminal provider overflow exits the native retry path for that step. Implement a bounded replan at a boundary that can replace the candidate without re-entering accepted-run, queue or tool execution callbacks. Key it to the actual adapter attempt and distinguish auth refresh from a change in routing options. In tests count transport attempts, callback invocations, user messages and tool dispatches. A successful smaller request with duplicate host events fails the test. A second overflow, unchanged candidate, or evidence of prior emitted output/tool effects ends automatic retry. Preserve the underlying cause. ### Storage and operation semantics

| Operation | Precondition, write and failure behavior |
|---|---|
| Finalize source | Upsert by host identity and expected source version, with digest and representation. Duplicate delivery of the same version/content is idempotent. Reject a digest conflict on the same version. An authorized edit advances the version and invalidates dependents. Synthetic repair records carry outcome-unknown, separate from tool-reported success/failure. |
| Publish checkpoint | Outside a transaction, generate from a frozen ordered range. Inside one transaction validate membership, source versions, applicable settings and predecessor, insert coverage, then conditionally switch pointer. Read through the transaction-bound querier. On conflict roll back all candidate rows. A new unrelated tail entry alone need not invalidate the candidate: re-read and validate that its covered prefix and current pointer are unchanged, and rebase the conditional publication against the current revision. Never blindly use a fresh revision with old evidence. |
| Expand retained source | Authenticate scope, check live source/version, validate range, verify digest against the stored representation, then return bounded content with handle and next range. Return opaque unavailable for unauthorized requests; for authorized owners distinguish expired, partial, missing and corrupt. Empty retained content and failed capture are distinct. |
| Forget a record | Revoke the accepted version, invalidate recall and cached selections, remove or recompute dependent derivatives and fence older queued results. Prevent automatic re-learning of a deliberately forgotten claim from the same evidence using minimal suppression metadata within policy. |
| Delete source/session | Compute dependent closure before cascades sever edges. Mark any dependent unknown-origin copy as such, rather than asserting precise erasure. |
| Concurrent dispatch and deletion | Define the dispatch decision’s linearization point. If revocation wins, abort/replan. Index source edges in both directions, revisions by owner, the active frontier by session and artifact cleanup work by state. Put scope into every direct lookup and join. SQLite foreign keys enforce referential integrity, not authority or derivative erasure. Exercise both supported SQLite implementations on their supported GOOS/GOARCH combinations. If FTS is unavailable, start with exact lookup and a bounded lexical fallback with an explicit incomplete status. Do not quietly rebuild an index in test setup to make a production write path pass.

### Artifact capture details

Follow `internal/shell/capped_buffer.go`, `stream.go`, `background.go`, `truncate.go` and `persist_message.go` from producer to transcript. Tee at the earliest reliable byte writer, before capped buffers, ANSI removal, formatting or combination. Trace Bash, job polling, direct-shell execution and persisted shell messages separately. Polling the same background job must reuse one producer-owned artifact and offset, not duplicate its storage. Never block forever on the artifact sink or convert a storage error into a successful command exit. Apply both per-artifact and aggregate quotas including temporary files. Store observed length separately from retained ranges; if the producer itself dropped bytes, mark the observed boundary unknown. Head/tail previews disclose omitted ranges. Before publishing a ready DB reference, close the writer and rename the verified temp file on the same filesystem. If claiming power-loss durability, sync file and directory using supported platform primitives and test that guarantee. A process crash between rename and commit leaves an orphan. Sweep only store-owned files after checking active writer/reservation state, and make cleanup idempotent; age alone cannot identify an orphan. Scope files by opaque IDs in an owned directory; reject path traversal and symlink substitution on expansion.

### Memory, search and task-state implementation

Deliver manual memory creation, edit, retrieval and forgetting before enabling automatic learning. Define a record with owner/scope, stable ID, type (preference, observation, decision, procedure or task note), topic, text, evidence, status and versions. For a manually entered claim, create a user-authored source/version and record deliberate scope. A manual edit creates new user evidence and retains provenance of any incorporated material. A direct user statement about a preference can support that preference. A pasted log inside a user message remains log evidence. A source-backed assertion describes what the source says; current repository state requires a revision or fresh inspection. Store conflicting observations with evidence and validity times. User editing or retracting a preference supersedes the prior version atomically. Default recall excludes needs-review, superseded, expired and retracted entries. Permit explicit inspection of retained versions subject to deletion policy.

After opt-in, enqueue extraction only for finalized, eligible groups. Job identity includes purpose, source version set and relevant policy/model configuration. Summarization and extraction are separate operations. Deduplicate pending work, bound concurrency, snapshot inputs, run model calls outside transactions, limit transient retries, then recheck sources and consent before commit. Rebuild missing work from retained source coverage after restart. An extraction error does not interrupt the user’s turn. Record extraction usage separately. Promote inferred candidates according to user policy; never automatically promote tool text into system or developer instructions.

Reuse session.Todos and its existing mutation path as the source of task-list status. Store a source/version reference when summarizing a todo. A checked todo by itself does not prove the corresponding tool succeeded. Invalidate the note after applicable todo edits or independent subagent changes. Keep one current task note per branch/session scope with goal, active constraints, decisions, files/revisions, verified progress, open questions, unresolved tool calls and next action. Update it after a meaningful transition with references to supporting results. A handoff to a new session is explicit, size-bounded, linked to the original and checked against the recipient’s authorization. Mark progress stale when files or branch identity change. Do not equate a Git branch name with an authorization principal.

Search exact handle/path first when applicable, then lexical matches in eligible finalized sources and active memories. Rank by applicability and evidence, use recency only when relevant, and collapse repeated derivatives of a single source. Return type, scoped handle, version, representation, excerpt and completeness. Retrieve by immutable file revision where available. For asynchronous or partial indexing, revalidate live rows and signal missing coverage/timeouts. Avoid caching initially. If measured cost requires caching, key by scope, authorization/policy generation, source/index version, query or model/render settings as applicable; revalidate before disclosure. A provider cache hit requires provider-reported evidence.

### User-control and retention decisions

Start the first opt-in slice with one explicitly named adapter and one local user. Name the tested model family, capabilities and request shapes in the implementing PR. Unsupported adapters retain ordinary Crush behavior or produce a documented capability result when strict UMCA behavior was requested. Expand adapter coverage independently after the same source and protocol gates pass. Production telemetry, an extra agent, cross-project discovery and a distributed job service are unnecessary for this slice.

Offer **remove from current context** as an operation on optional material, distinct from forgetting learned memory and deleting retained sources. Bind a hide/pin decision to scope and source version; expose its reason and removal in the inspector. Keep required provider parts intact. Pins cannot override revocation or access control. When pins and required content exceed capacity, report the conflict and allow a user to unpin, revise input or select a compatible model. Historical instructions preserve original authority and applicability; quoting them in a summary cannot grant them new authority over the current user.

Suppress additional UMCA indexing, capture, export and model-based extraction independently when the user opts out. Parent and child sessions have separate source identities. Default to retaining independent child content while invalidating any traced derivatives of a deleted parent source, and offer explicit deletion of a selected subtree. Never grant child, channel or sibling recall solely by matching filesystem paths. Mark a derived record blocked until its surviving sources have been revalidated. Keep negative suppression metadata minimal and content-free where possible. Restoring a pre-deletion backup can resurrect forgotten data: quarantine it for explicit restore/import and apply available revocations before enabling recall. Report any missing revocation history. Local logical deletion does not guarantee forensic erasure from SQLite free pages, WAL, snapshots, or copies outside host control.

For ingestion, a repeated event ID **and version** with a different payload is a conflict, not an authorized update. Accept legitimate edits only through a new source version with an expected predecessor. For partial capture, store ranges with offsets in the original stream where known, digest each available range and mark gaps. Never concatenate head and tail and advertise the result as a contiguous original. Cap both expansion I/O and returned bytes. If full-file verification would require reading an unbounded file per small excerpt, verify authenticated chunks against a trusted manifest or verify once at ingestion and revalidate against replacement/corruption under the store’s access model. Do not claim full-file verification from a checked excerpt.

Define summary acceptance on the actual summarizer response. A transmission error, length stop or missing required source group cannot publish. When a provider omits the finish reason, either establish completion through a supported adapter contract or defer the checkpoint. Preserve Crush’s cost accounting for a failed or rejected summary without activating it. Keep the last valid projection **only while all its inputs remain authorized**. Otherwise reconstruct from surviving sources, or stop with a recoverable status.

## 11. Full implementation beyond the first vertical slice

Stages 1–6 in §6 establish the shared host, storage and permission contracts. **Ship every capability below as part of the complete implementation.** A gate protects activation, data access, spending or rollout. An unmet gate leaves that capability open in the implementation ledger. Users can keep paid processing, remote storage, personal recall and other modes disabled indefinitely. Implement and test both the enabled and disabled paths.

The following are proposed engineering choices for Crush. Use the pinned XRush sources and fixture mappings in [§8](#8-xrush-implementation-references-and-regression-risks) alongside the external reference index. Keep SQLite and the existing workspace API as the default deployment. Use one authoritative copy of each record per scope; derived indexes may be rebuilt. Put new features behind the same inspect, forget and deletion interfaces. Every async job and derived record carries a resolvable owner, source versions, effective policy generation, producer version and lifecycle state. ### A. Multi-level context, pressure and rollover

**Prerequisite:** checkpoint publication, expansion and tool-group tests in §§3–7. Start from XRush’s lineage and preserved-context fixtures in §8, then assert that the next Crush request consumes the projected frontier. Extend the rolling checkpoint with ordered child edges, level, branch, first/last covered event and coverage digest. Select adjacent, settled siblings on the same branch. Budget the condensation call independently; validate coverage against the union of children, then compare-and-swap the frontier. A parent may refer to several children. Require an acyclic graph, prohibit overlapping primary coverage and retain a bounded expansion traversal with cycle detection. A missing or expired original is reported at its actual position. Descendant deletion invalidates all covering ancestors before they can be selected. Keep one published checkpoint frontier per independently writable conversation lineage. When each branch is a distinct Crush session, the session ID is sufficient. Each request derives its own view; two sibling runs must never share a mutable active view. Git branch names and parent-session metadata cannot establish that two lineages inherited the same conversation.

Add compartments for current task, earlier tasks, repo evidence, preferences and archived details. Assign items by typed provenance and explicit task boundaries. Put each optional item at a chosen detail level (full, excerpt, summary or handle). Score optional items using task relevance, age, explicit importance and current budget pressure; record the contributions in the inspector. Apply stable tie-breaking and hysteresis between pressure bands to prevent churn near a threshold. Reserve mandatory content first. Decay changes presentation only; it cannot change a fact's authority, erase evidence or override a pin. Run proactive summarization on a frozen eligible prefix during idle time. Abort on invalidation, account for its cost and keep an on-demand path if it misses the deadline.

For rollover, atomically record source branch/frontier, a task note, retained tail and pending-operation handles under an idempotency key. Create the new session with explicit user/host authorization and a scoped handoff reference. Render and budget the recipient view before committing activation. If publication crosses stores, use stage H's recoverable handoff protocol. Preserve independent continuation of the original branch. Do not resume an external side effect whose outcome is unknown.

**Acceptance:** expand a three-level checkpoint to the original ordered IDs, invalidate a middle leaf, compare two siblings after a fork, oscillate the budget around a pressure threshold, interrupt proactive summarization, and retry an already-created rollover. Require one handoff, no duplicate coverage, no leaked sibling content and a legal outgoing tool history.

1. **Preflight.** Resolve the point and compute the desired before-images by folding the mutation log after the target in reverse, using versions and expected after-images. Apply operations only when their preconditions still hold and expose any race that cannot be resolved safely.
3. **Apply and publish.** Stage files in the target filesystem and use supported atomic replacement per regular file. Journal intent before changing each path and record the result afterward. Represent partial states honestly across files. After confirmed workspace success, compare the operation fence, expected frontier, source validity and current policy in the publication transaction. Commit the new conversation frontier, active-lineage eligibility changes and journal status together. A failed comparison enters recovery even when all files were applied. Workspace-only publication records a workspace revision and marks affected evidence stale. Conversation-only publication uses the same conditional frontier transaction without file I/O. If the workspace journal and authoritative frontier use separate stores, persist a per-operation publication receipt with the frontier mutation. Retry by checking that receipt before deciding to compensate. An unknown database commit outcome keeps affected runs gated until the authoritative decision is known. Reconcile checkpoint coverage, observation/reflection cursors, task notes, pending workers, memory and search eligibility. For workspace-only changes, invalidate stale file/repo evidence even though old messages remain readable. For conversation-only changes, default recall and learning exclude the abandoned suffix and derivatives that depend on it. Keep independently supported memories if their evidence still validates. This operation does not give a revoked source new authority through a fork, cache or later worker completion.
4. **Recover.** On restart, inspect each unapplied or ambiguous intent and compare observed fingerprints with the expected pre- and post-state. Reconcile or compensate only when the known state matches and permissions still hold. If a third-party change or lost snapshot makes the result ambiguous, return `needs_resolution` with paths and affected conversation status. Preserve the recovery journal, keep the new frontier unpublished unless its workspace state succeeded, and offer an explicit retry or recovery operation. After an authoritative abort decision, unwind confirmed changes in reverse order only while their applied fingerprints still match. Record compensation intents and outcomes durably. Restore the pre-apply state, including originally absent paths, or report the unresolved paths. Cancellation after the first mutation uses this same recovery path. A retry after a committed response was lost returns the existing result. A restore failure never claims an atomic operation across the filesystem and database. Use the same idempotency key across local and connected retries, and reject it if the requested preview or mode differs.

Deletion and expiration apply to snapshot before-images, orphaned lineage references and journal payloads. Reserve recovery capacity and pin already authorized payloads against ordinary eviction while an operation is unresolved. A revocation takes precedence over that pin. Invalidate the affected operation, recheck remaining eligibility, and report any compensation blocked by unavailable bytes without retaining a hidden copy. File and conversation rollback do not revoke independent sources or automatically undo Git staging, network actions, or past model disclosures. Keep minimal operation metadata where policy permits a record of the outcome. User-visible inspection distinguishes captured, unavailable, conflicted, applied and compensated paths. Log IDs, bounded status and counts by default. Existing conversations without recorded mutation history may offer conversation-only rewind at a validated boundary. File rewind for those turns requires independent captured evidence.

**Acceptance:** exercise workspace-only, conversation-only, combined and fork operations through the real workspace API and CLI/TUI flows. Cover binary bytes and file modes, a new file, a delete, a rename, unrelated dirty/staged changes and an externally modified target. Cover a path moved or replaced after preview, an expired snapshot, a shell capture gap, an in-flight subagent and a provider-signed boundary. Inject a failure after one file mutation and before frontier publication, restart across each journal boundary, and check honest partial reporting, safe compensation and idempotent retry. Verify that the next real provider call contains the intended prefix, excludes abandoned or revoked material and never re-executes a prior tool. Delete an inherited source and test fork, recall, historical query and snapshot expansion. Also race revocation with apply, interrupt between two mutations on the same path, simulate a sibling session editing the target and lose the response after the authoritative commit. Verify queued work and a retried client receive one consistent terminal result, including when journal and frontier use separate stores. Adapt the XRush mode and error fixtures, then exercise the UMCA storage and host boundaries they do not cover. ### Integration contracts shared by the advanced stages

**User and agent entry points.** Register read-only `context_search` and `context_expand` through the normal tool resolver with the same allowed-tool filtering as native tools. Proposed search input is query, requested scope, kinds, bounded limit and cursor. Return source handle/version, timestamp, kind, representation, capture status, bounded snippet, retrieval method and continuation/completeness. Expand accepts a scoped handle and either half-open byte offsets or a bounded line interval for a known text representation; resolve line boundaries against that immutable version. Reject mixed units, arbitrary filesystem paths and invalid ranges. Both tools apply server-side limits even if the caller asks for more. For MCP, use the same operations and response semantics. Return an explicit unavailable or incomplete status when a gate closes. An expansion cursor binds source/version, representation, next range, requester scope and policy revision. A search cursor also binds the normalized query, ranking/index generation and a deterministic tie break. Reject stale, altered and cross-scope cursors. Resume through the owned storage locator and recheck authorization immediately before returning excerpts. Expose metadata-only errors when the requested handle is outside the caller’s scope.

**Capture and egress policy.** Derive a searchable projection from explicitly allowed text parts. Exclude opaque reasoning signatures, binary encodings, credential fields and serialized metadata from search, embeddings, helper input and export unless a specific safe representation is approved. Preserve provider-required opaque data only under the original history/continuation policy. Apply capture exclusions before durable storage. Mark a filtered representation redacted or partial, record the policy version, and never promise byte-exact recovery of removed content. Index deletion and policy tightening must invalidate derived vectors, queued model inputs, receipts containing source excerpts, and shared-store copies. Tests seed deterministic synthetic secrets in allowed text, excluded fields and stderr; verify the configured exclusions across native search, external model inputs, MCP, diagnostics and exports. Pattern matching cannot guarantee detection of every secret.

**Stage rollout and evidence.** For each A–I stage, add a default-safe configuration path, a deterministic integration fixture and a rollback exercise. Expose switches through Crush configuration plus workspace-visible state. Separate permissions for capture, background model spending, remote embedding/reranking, remote storage, personal sharing and MCP exposure. A deployment choice cannot grant a previously denied content permission. On schema/index upgrades build a shadow generation, validate coverage and expected results, switch the reader atomically and retain a bounded rollback window. A rollback must enforce all current revocations. An operator must be able to inspect failed items, retry idempotently, rebuild a derivative index from authorized sources and distinguish a service outage from no matching evidence.

### Completion and operation

A–I are required implementation streams. A and B build on checkpoint and memory storage; C and F build on scoped recall and invalidation; D consumes the bounded recall API; E and G share adapter fixtures; H supplies cross-store and multi-worker durability. I depends on the local capture, frontier and deletion contracts plus workspace mutation coordination. The local rewind implementation can proceed alongside the distributed backend. An implementer can use a local transactional fake for cross-store events during development, but F and external projections cannot pass their deployment gates until H's partition and recovery tests pass. Each implementation PR names its storage migrations, configuration/consent switches, user-visible entry point, metrics, rollback procedure and acceptance fixtures. Expose per-capability status in inspection: implemented/version, enabled for this caller, unavailable reason, last successful validation, cost/retention policy. Disabling a capability stops new jobs and publications, preserves authorized inspection/deletion, and falls back to the tested simpler path. The complete release requires §§6–7 plus A–I demonstrated through their real host entry points. A disabled-by-default implementation needs a passing enabled-path test. Record the operator-visible permission and the slower or degraded path taken when a capability is unavailable.
